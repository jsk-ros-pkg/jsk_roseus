## ROS 2

`roseus`, `roseus_smach`, `roseus_mongo` and `roseus_tutorials` build on both ROS 1 (catkin) and ROS 2 (ament), with the same euslisp API.

```bash
sudo apt install euslisp euslisp-dev jskeus   # Ubuntu 26.04
# Ubuntu 24.04: jskeus is not in the archive yet, use ppa:k-okada/euslisp
mkdir -p ~/ros2_ws/src && cd ~/ros2_ws/src
git clone https://github.com/jsk-ros-pkg/jsk_roseus.git
cd ~/ros2_ws && rosdep install --from-paths src -i -y && colcon build
source install/setup.bash
roseus   # (ros::roseus "foo") (ros::advertise "chatter" std_msgs::String 1) ...
```

- Messages: the euslisp classes serialize the CDR payload themselves, and `roseus.so` uses `rclcpp::GenericPublisher`/`GenericSubscription`. They are generated by `rosidl_generator_eus`: interface packages built after it install them in `share/roseus/ros/<pkg>`, the others are generated on demand in `$ROS_HOME/roseus/$ROS_DISTRO` (and regenerated when the `.msg` files are updated). `builtin_interfaces/Time` and `Duration` are `ros::time` and `ros::duration`, ROS 2 `std_msgs/Header` has no `seq`.
- Services: `ros::service-call`, `ros::advertise-service` as ROS 1. Also `ros::service-call-async`, and a service callback can return `:deferred` to send the response later with `(ros::send-service-response (ros::service-request-handle) res)`.
- Actions: `ros::simple-action-client` / `ros::simple-action-server` with the ROS 1 API on top of the ROS 2 action protocol, they talk to `rclcpp_action` / `rclpy.action`. `pkg::FooAction`, `pkg::FooActionGoal` are aliases of `pkg::Foo`, `pkg::Foo_SendGoalRequest`, and `:get-state` returns the ROS 1 `actionlib_msgs::GoalStatus::*...*`.
- tf: `ros::transform-listener`, `ros::transform-broadcaster`, `ros::buffer-client` on tf2_ros.
- Parameters: there is no parameter server, `ros::get-param`/`ros::set-param` use the parameters of this node (`"~foo"`, `"foo"` and `"/foo"` are `foo`, `"a/b"` is `a.b`). `ros::get-node-param`/`ros::set-node-param` get/set the parameters of other nodes, which replace dynamic_reconfigure (`ros::set-dynamic-reconfigure-param` calls `ros::set-node-param`).
- Arguments of ROS 1 (`a:=b`, `_param:=value`, `__name:=`, `__ns:=`) are converted to `--ros-args`.
- Not supported: `ros::get-host`, `ros::get-uri`, `ros::get-port` (no ROS master), `ros::rospack-plugins`, `ros::anymsg`.

## Tips

### History in the interpreter

When `rlwrap` is installed, `roseus` started from a terminal uses it for the line editing and the history (C-p, C-r, ...), which are saved in `~/.roseus_history` (`$ROSEUS_HISTORY`). Set `ROSEUS_NO_RLWRAP=1` to disable it, it is not used in emacs.

### Run roseus on gdb
```
roseus --gdb foo.l
```


### Use roseus with euslisp built from source

To use euslisp built from source, we need to create upstream workspace and then overlay it to your workspace.

1. Create the upstream workspace

    Assumes you already installed `ros-<your distro>-desktop-full`.

    ```bash
    source /opt/ros/<your distro>/setup.bash
    mkdir -p ~/ros/$ROS_DISTRO_parent/src/
    cd ~/ros/$ROS_DISTRO_parent/src
    wstool init
    wget https://raw.githubusercontent.com/jsk-ros-pkg/jsk_roseus/master/setup_upstream.sh -O /tmp/setup_upstream.sh
    bash /tmp/setup_upstream.sh -w ..
    cd ~/ros/$ROS_DISTRO_parent/
    catkin init
    catkin config --cmake-args -DCMAKE_BUILD_TYPE=RelWithDebInfo  # This is optional
    catkin build
    source ~/ros/$ROS_DISTRO_parent/devel/setup.bash
    ```
    
    You can check if `euslisp` built from source is available by running `which irteusgl`.

2. Build downstream packages using euslisp built from source

    Configure your catkin workspace to overlay the upstream workspace and build `roseus`.
    
    ```bash
    mkdir -p ~/ros/$ROS_DISTRO/src  # If you not yet create your workspace
    cd ~/ros/$ROS_DISTRO/src
    wstool init  # If you don't yet create your workspace
    wstool set jsk-ros-pkg/jsk_roseus --git https://github.com/jsk-ros-pkg/jsk_roseus.git -v master -u -y
    rosdep install --from-paths . -i -r -n -y  # By running this, all dependencies will be installed
    cd ~/ros/$ROS_DISTRO
    catkin init  # If you don't yet create your workspace
    catkin config --cmake-args -DCMAKE_BUILD_TYPE=RelWithDebInfo  # This is optional
    catkin build roseus
    source ~/ros/$ROS_DISTRO/devel/setup.bash
    ```
